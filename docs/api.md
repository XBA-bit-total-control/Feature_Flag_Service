# Руководство по API

При стандартном запуске API доступен на `http://127.0.0.1:8000`. Полные схемы запросов и ответов смотрите в [Swagger UI](http://127.0.0.1:8000/docs), [ReDoc](http://127.0.0.1:8000/redoc) или [OpenAPI JSON](http://127.0.0.1:8000/openapi.json). Если порт изменён, подставьте его в ссылки и примеры.

Для запуска используйте [руководство](getting-started.md), а для последовательности запросов от создания флага до отчёта — [демо](demo.md).

## Аутентификация и доступ

`POST /auth/login` принимает JSON с `email` и `password`. Передавайте `access_token` из ответа в заголовке `Authorization: Bearer <JWT>`. Роль проверяется по текущей записи пользователя в PostgreSQL, поэтому изменение роли действует и для ранее выданных действующих токенов. Диалог OAuth2 «Authorize» в Swagger UI отправляет данные формы, поэтому для JSON-входа и защищённых примеров ниже используйте HTTP-клиент с явно заданным заголовком Bearer.

| __Роль__          | __Права__                                                                                                                                         |
|-------------------|---------------------------------------------------------------------------------------------------------------------------------------------------|
| __`viewer`__      | Роль при регистрации. Может читать свой профиль, таргетинг собственных флагов и эксперименты этих флагов с результатами и отчётами.               |
| __`developer`__   | Дополнительно может создавать флаги и изменять собственные ресурсы, запускать их эксперименты, пересчитывать результаты и запрашивать LLM-отчёты. |
| __`admin`__       | Может управлять ресурсами всех владельцев и назначать роли. Попытка понизить роль действующего администратора через API возвращает `409`.         |

Владельцем эксперимента считается владелец связанного флага. Поле `creator_id` показывает, кто создал эксперимент, и может отличаться от владельца, если его создал администратор. Публичные операции включают чтение флагов и вариантов, `/resolve` и приём событий.

| __Маршрут__                              | __Условие вызова и результат__                                                                                |
|------------------------------------------|---------------------------------------------------------------------------------------------------------------|
| __`POST /auth/register`__                | Публичный. Создаёт пользователя с ролью `viewer`, ответ `201`. Зарегистрированный email даёт `400`.           |
| __`POST /auth/login`__                   | Публичный. Возвращает токен, ответ `200`. Неизвестный email и неверный пароль дают одинаковый ответ `401`.    |
| __`GET /auth/me`__                       | Bearer-токен. Возвращает профиль и роль.                                                                      |
| __`PATCH /auth/users/{user_id}/role`__   | Администратор. Принимает, например, `{"role":"developer"}`. `user_id` здесь — UUID учётной записи оператора.  |

Пример входа в PowerShell 7. Используйте данные зарегистрированного аккаунта.

```powershell
$api = 'http://127.0.0.1:8000'
$email = Read-Host 'Email'
$password = Read-Host 'Пароль' -MaskInput
$login = Invoke-RestMethod -Method Post -Uri "$api/auth/login" -ContentType 'application/json' -Body (@{
    email = $email
    password = $password
} | ConvertTo-Json)
$auth = @{ Authorization = "Bearer $($login.access_token)" }
Invoke-RestMethod -Uri "$api/auth/me" -Headers $auth
```

## Флаги, варианты и таргетинг

`{key}` — строковый ключ флага. `flag_id`, `{variant_id}` и `{rule_id}` — UUID разных сущностей. При создании варианта передайте UUID флага в `flag_id` и его ключ в URL. Родительский флаг определяется по URL. Для изменения собственного флага нужна роль `developer`, администратор может изменять любой флаг.

| __Маршрут__                                        | Условие вызова и результат                                                                                                                                        |
|----------------------------------------------------|-------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| __`GET /api/flags`__                               | Публичный список флагов. Поддерживает фильтры и пагинацию.                                                                                                        |
| __`POST /api/flags`__                              | `developer` или `admin`. Создаёт флаг, ответ `201`. Ключ должен быть уникальным.                                                                                  |
| __`GET /api/flags/{key}`__                         | Публичное чтение флага по ключу.                                                                                                                                  |
| __`PATCH /api/flags/{key}`__                       | Владелец с правом записи или администратор. Обновляет переданные поля.                                                                                            |
| __`DELETE /api/flags/{key}`__                      | Владелец с правом записи или администратор. Мягко удаляет флаг, ответ `204`. Ключ остаётся занятым, история экспериментов сохраняется.                            |
| __`GET /api/flags/{key}/variants`__                | Публичный список вариантов флага.                                                                                                                                 |
| __`POST /api/flags/{key}/variants`__               | Владелец с правом записи или администратор. Добавляет вариант, ответ `201`. Ключ варианта уникален в пределах флага.                                              |
| __`GET /api/flags/variants/{variant_id}`__         | Публичное чтение варианта по UUID.                                                                                                                                |
| __`PATCH /api/flags/variants/{variant_id}`__       | Владелец с правом записи или администратор. Изменяет поля варианта по UUID.                                                                                       |
| __`DELETE /api/flags/variants/{variant_id}`__      | Владелец с правом записи или администратор. Удаляет вариант, ответ `204`.                                                                                         |
| __`GET /api/flags/{key}/targeting`__               | Bearer-токен владельца флага или администратора. Возвращает правила, включая отключённые.                                                                         |
| __`POST /api/flags/{key}/targeting`__              | Владелец с правом записи или администратор. Добавляет правило, ответ `201`.                                                                                       |
| __`PUT /api/flags/{key}/targeting/{rule_id}`__     | Владелец с правом записи или администратор. Полностью заменяет правило указанного флага. Для отключения передайте `is_enabled: false` вместе с остальными полями. |
| __`DELETE /api/flags/{key}/targeting/{rule_id}`__  | Владелец с правом записи или администратор. Удаляет правило указанного флага, ответ `204`.                                                                        |

Флаг с запущенным или приостановленным экспериментом нельзя переименовать или удалить. Для такого флага также запрещено добавлять и удалять варианты, менять их ключи и веса. Эти операции возвращают `409`.

Пример флага, который включает функциональность для части пользователей.

```http
POST /api/flags
Authorization: Bearer <JWT>
Content-Type: application/json

{
    "key":"checkout",
    "type":"percentage",
    "enabled":true,
    "rollout_percentage":25
}
```

## Назначение варианта и приём событий:

| __Маршрут__                   | __Условие вызова и результат__                                                                                                                   |
|-------------------------------|--------------------------------------------------------------------------------------------------------------------------------------------------|
| __`POST /resolve`__           | Публичный. Возвращает решение для `flag_key`, клиентского `user_id` и необязательных `attributes`. При успешном A/B-назначении сохраняет показ.  |
| __`POST /api/events/single`__ | Публичный. Сохраняет одно событие, ответ `201` с идентификатором документа.                                                                      |
| __`POST /api/events`__        | Публичный. Принимает объект `{"events":[...]}` с 1–100 событиями. Успешный ответ `201` содержит `accepted` и `rejected`.                         |

В `/resolve` вместо `user_id` можно передать `user_identifier`. Если указаны оба поля, значения должны совпадать. При выключенном флаге или отказе таргетинга ожидается `200` с `enabled: false` и причиной в `reason`. Для A/B-назначения используйте `variant` и `experiment_id` из ответа. `user_id` здесь — идентификатор участника в клиентской системе.

Для примеров назначения и конверсии предполагается запущенный A/B-эксперимент с метрикой `purchase` на флаге `checkout-ab`. Настройка такого эксперимента показана в [демо](demo.md).

```http
POST /resolve
Content-Type: application/json

{
    "flag_key":"checkout-ab",
    "user_id":"customer-42",
    "attributes":{"country":"RU"}
}
```

Успешное A/B-назначение уже записывает `impression`. Чтобы засчитать конверсию, передайте те же `flag_key`, `user_id`, UUID эксперимента и полученный вариант в `variant_key`. `event_name` должен совпадать с `primary_metric` эксперимента, а время конверсии должно быть не раньше показа. UUID и вариант ниже показаны для примера, подставьте свои значения из `/resolve`.

```http
POST /api/events/single
Content-Type: application/json

{
  "event_type": "conversion",
  "event_name": "purchase",
  "flag_key": "checkout-ab",
  "user_id": "customer-42",
  "experiment_id": "11111111-1111-4111-8111-111111111111",
  "variant_key": "B"
}
```

При указанном `experiment_id` API требует запущенный эксперимент и проверяет принадлежность флага и варианта. Ошибка связи даёт `422` до записи пакета. При сбое самой пакетной вставки часть документов может быть уже сохранена, поэтому повтор всей пачки способен создать дубликаты.

## Эксперименты, результаты и отчёты:

Для всех маршрутов экспериментов нужен Bearer-токен. Читать эксперимент может владелец флага или администратор. Для изменений, ручного пересчёта и запроса LLM-отчёта дополнительно требуется право записи.

| __Маршрут__                                                  | __Условие вызова и результат__                                                                                                               |
|--------------------------------------------------------------|----------------------------------------------------------------------------------------------------------------------------------------------|
| __`GET /api/experiments`__                                   | Список экспериментов доступных флагов. Администратор видит все. Поддерживает фильтры и пагинацию.                                            |
| __`POST /api/experiments`__                                  | Создаёт черновик для флага из `flag_id`, ответ `201`. Имя эксперимента уникально.                                                            |
| __`GET /api/experiments/{experiment_id}`__                   | Читает параметры и текущее состояние эксперимента.                                                                                           |
| __`PATCH /api/experiments/{experiment_id}`__                 | Меняет параметры черновика или выполняет переход статуса. Для перехода передайте отдельное тело с `status`, например `{"status":"running"}`. |
| __`DELETE /api/experiments/{experiment_id}`__                | Удаляет только черновик, ответ `204`.                                                                                                        |
| __`GET /api/experiments/{experiment_id}/results`__           | Возвращает последние сохранённые результаты. До первого расчёта возвращает пустой массив.                                                    |
| __`POST /api/experiments/{experiment_id}/results`__          | Сразу пересчитывает результаты запущенного или приостановленного эксперимента. Тело запроса не требуется.                                    |
| __`GET /api/experiments/{experiment_id}/template/reports`__  | Сразу строит шаблон по сохранённым результатам, без постановки задачи и записи в историю.                                                    |
| __`POST /api/experiments/{experiment_id}/llm/reports`__      | Сохраняет задачу и её входной снимок, ответ `202`. Пока задача с тем же снимком в `pending`, повтор возвращает тот же `id`.                  |
| __`GET /api/experiments/{experiment_id}/reports`__           | Возвращает историю отчётов и состояние задач. Сопоставьте `id` с ответом на POST.                                                            |

Для расчёта нужны ровно два варианта. Контрольный вариант должен называться `control` или `A`. Сначала сохраните результаты, затем запрашивайте шаблон или LLM-отчёт. При отсутствии подходящего снимка запрос отчёта вернёт `409`.

В истории `pending` означает ожидание обработки, `completed` — готовый результат. При отсутствии ключа LLM или сбое генерации готовый результат может иметь `report_type: template` и заполненное `fallback_reason`. `failed` используется, например, для старого задания без входного снимка. Автоматические шаблоны после значимого планового расчёта также видны в истории.

## Фильтры и пагинация:

| __Список__                  | __Фильтры__                                                                                  | __Порядок__                                        |
|-----------------------------|----------------------------------------------------------------------------------------------|----------------------------------------------------|
| __`GET /api/flags`__        | `type` — точное значение типа, `enabled` — `true` или `false`.                               | По ключу флага.                                    |
| __`GET /api/experiments`__  | `status` — `draft`, `running`, `paused`, `completed` или `stopped`, `flag_id` — UUID флага.  | По дате создания от новых к старым, затем по UUID. |

Оба списка принимают `limit` от 1 до 100, по умолчанию 100, и `offset` от 0 до 2147483647, по умолчанию 0. Ответ — массив. Для следующей страницы увеличьте `offset` на размер страницы. Пример запроса второй страницы по 20 включённых флагов типа `percentage`.

```http
GET /api/flags?type=percentage&enabled=true&limit=20&offset=20
```

## Типовые ошибки:

| __HTTP__                       | __Когда возникает__                                                                                                          |
|--------------------------------|------------------------------------------------------------------------------------------------------------------------------|
| __`400 Bad Request`__          | Повторная регистрация email, пустой PATCH флага или варианта, недопустимый `null` в их полях.                                |
| __`401 Unauthorized`__         | Неверные данные входа, отсутствующий, недействительный или просроченный токен, либо учётная запись токена больше недоступна. |
| __`403 Forbidden`__            | Токен действителен, но роль или владение ресурсом не дают нужных прав.                                                       |
| __`404 Not Found`__            | Ресурс отсутствует, архивный флаг скрыт либо правило запрошено по ключу другого флага.                                       |
| __`409 Conflict`__             | Дублирующийся ключ, недопустимый переход состояния, конфликт с активным экспериментом или отсутствующий снимок для отчёта.   |
| __`422 Unprocessable Entity`__ | Некорректный JSON, параметры, UUID или связи события с экспериментом.                                                        |
| __`503 Service Unavailable`__  | Недоступная БД в readiness или сбой MongoDB при приёме, записи показа или расчёте результатов.                               |

У ошибок API подробности находятся в `detail`. При валидации FastAPI это обычно массив с полями и причинами. `204 No Content` означает успешное удаление с пустым телом ответа, а `202 Accepted` подтверждает создание или переиспользование задания, готовый отчёт читайте в истории.
